# 1. Синхронизация по PSS

## 1.1. Теоретические сведения

Primary Synchronization Signal (PSS) — первичный сигнал синхронизации LTE, предназначенный для обнаружения соты и выполнения первичной временной синхронизации.

PSS передаётся два раза в радиокадре. Для LTE FDD он располагается в OFDM-символе 6 сабфрейме 0 и OFDM-символе 6 сабфрейма 5.

В качестве PSS используется последовательность Zadoff–Chu. В зависимости от значения последовательности определяется компонент `N_ID^(2)`:

$$
N_{ID}^{(2)} \in \{0,1,2\}.
$$

Идентификатор физической соты впоследствии вычисляется как

$$
N_{cell}^{ID} = 3N_{ID}^{(1)} + N_{ID}^{(2)}.
$$

где:

- $N_{ID}^{(1)}$ — номер группы физической соты;
- $N_{ID}^{(2)}$ — номер последовательности PSS;
- $N_{cell}^{ID}$ — полный идентификатор физической соты.

## 1.2. Алгоритм синхронизации

Для обнаружения PSS использовалась корреляция принятого сигнала с локально сгенерированными PSS-последовательностями.

Общая схема обработки:

```text
Принятый сигнал
       │
       ▼
Генерация PSS (3 варианта)
(по статье sharedtechnote)
       │
       ▼
Корреляция
       │
       ▼
Поиск максимума
       │
       ▼
Положение PSS + N_ID^(2)
```

### Реализация

```text
1. Сформировать три возможные последовательности PSS.
2. Выполнить корреляцию каждой последовательности с принятым сигналом.
3. Найти максимумы корреляционных функций.
4. Выбрать последовательность с максимальным значением корреляции.
5. Зафиксировать положение PSS во временной области.
6. Определить N_ID^(2).
```

# 2. Синхронизация по SSS и определение Cell ID

## 2.1. Теоретические сведения

Secondary Synchronization Signal (SSS) используется совместно с PSS для определения положения радиокадра и полного идентификатора физической соты.

В отличие от PSS, SSS позволяет определить $N_{ID}^{(1)}$. После определения обоих компонентов идентификатор соты вычисляется по формуле:

$$
N_{cell}^{ID} = 3N_{ID}^{(1)} + N_{ID}^{(2)}.
$$

Для LTE существует:

$$
N_{ID}^{(1)} \in [0,167],
$$

а следовательно, всего возможно 504 различных идентификатора физических сот:

$$
N_{cell}^{ID} \in [0,503].
$$

SSS расположен непосредственно **перед PSS** в рассматриваемом субкадре:

```text
SSS → PSS → PBCH
```

Для LTE FDD в подкадре 0:

```text
OFDM symbol:
4   5   6   7   8   9   10
    SSS PSS PBCH PBCH PBCH PBCH
```

## 2.2. Алгоритм поиска SSS

После обнаружения PSS его положение используется для определения возможного положения SSS.

Общая схема:

```text
       PSS
        │
        ▼
Определение позиции SSS
        │
        ▼
Генерация кандидатов SSS
(по статье sharedtechnote)
        │
        ▼
    Корреляция
        │
        ▼
    N_ID^(1)
        │
        ▼
    Cell ID
```

**Найденное положение SSS:**

После синхры по PSS у нас осталась позиция начала PSS символа (pss_start).
Тогда положение SSS можно найти как:

$pss_start - (fft\_size + cp\_size)$,   где fft_size = 128, cp_size = 9

**Определённое значение N_ID^(1):**

N_ID^(1) = 22, correlation = 0.99707174

**Вычисленный Cell ID:**

$$
N_{cell}^{ID} = 3 \cdot 22 + 1 = SIX \ \  SEVEN
$$

# 3. Декодирование PBCH

## 3.1. Теоретические сведения

Physical Broadcast Channel (PBCH) предназначен для передачи системной информации, необходимой для работы пользовательского оборудования в LTE.

PBCH передаётся в четырёх OFDM-символах первого подкадра в каждом фрейме.

## 3.2. Выделение PBCH

После определения положения PSS и SSS положение PBCH определяется относительно PSS:

```text
SSS → PSS → PBCH → PBCH → PBCH → PBCH
```

Если индекс `start_pss_index` указывает на начало PSS OFDM-символа, то начало первого PBCH OFDM-символа определяется как:

```rust
let symbol_len =
    config.cp_type.size() as usize + config.dl_bw.fft_size();

let start_pbch = start_pss_index + symbol_len;
```

После этого выделяются четыре OFDM-символа PBCH.

## 3.3. FFT и выделение RE

Для каждого OFDM-символа выполняется:

```text
Временной сигнал
      │
      ▼
  Удаление CP
      │
      ▼
     FFT
      │
      ▼
Выделение 72 центральных subcarriers
      │
      ▼
  Удаление CRS
      │
      ▼
  240 PBCH RE
```

## 3.4. QPSK-демодуляция

PBCH использует QPSK. После выделения 240 PBCH RE строится диаграмма созвездия.

Ожидаемая структура:

```text
       Q
       ↑
       │    ●       ●
       │
       │
───────┼──────────────→ I
       │
       │    ●       ●
       │
```

На практике расположение точек может отличаться от идеального из-за:

- шума;
- частотной ошибки;
- фазовой ошибки;
- многолучевого распространения;
- ошибок временной синхронизации;
- влияния канала;
- несовершенной оценки канала.

## 3.5. Попытка декодирования PBCH

После QPSK-демодуляции полученная последовательность должна пройти дальнейшие этапы обработки:

```text
240 QPSK RE
     │

     │
     ▼
Descrambling
(с использованием CellId)
     │
     ▼
inverse rate matching
     │
     ▼
convolutional processing
     │
     ▼
    CRC
     │
     ▼
    MIB
```
